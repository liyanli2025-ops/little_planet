# 阿球 Echoo · 双人云存档版

**打个喷嚏，是有人在惦记你。**

「阿球」取打喷嚏「阿秋」的谐音，把被惦记的温暖藏进名字里；英文名为 **Echoo**。

两个人各有一颗可以行走、旋转、进入小屋的 3D 星球。白熊“小禾”和棕熊“阿远”分别属于两个独立账号，用一次性邀请码配对后，能够异步互访、赠送零食、留饭、写共同手账。

## 这一版已经实现

- 两层小屋：一层厨房与客厅，楼梯通往二层卧室；床可躺下休息、起床，休息写入手账。二层有床头灯、书架和书桌，上楼时展开二层视图。修正站立、步行、长椅与露营坐姿的接触高度。
- 星球和小屋占满一屏；页面不横向滚动，仍可拖动旋转星球。日常卡片、探索入口和天气控制收进右侧「日常」面板，点击展开。
- 两个真实账号：用户名和密码登录、服务器端固定角色、退出登录和管理员密码重置。
- 设备时钟与所在地天气：真实天气模式进入时自动获取设备大致位置（需 HTTPS 与用户授权），定位失败可选城市；Open-Meteo 自动同步温度、晴雨雪与日出日落，互访显示对方所在地时区；支持 HTTPS 设备定位和手动天气。
- SQLite 云端存档：冰箱、饭菜、随身包、庭院花盆、帐篷、宠物互动计数、足迹、手账、纪念日和珍藏。
- 24 小时有效的一次性配对邀请码；未配对不能访问对方的星球，支持解除配对。
- 异步互访：对方离线时也可以去做客，给对方留零食、做饭；接收方登录后发现、食用，并更新双方记录。
- 私人手账由服务器过滤，只传给本人；共同回忆和留言由双方查看。对方不能修改你的私人包、珍藏、天气或装扮，也不能冒充你写记录。
- 事务保存、版本冲突检查和重复提交保护；页面显示保存状态，断网或冲突时可以导出未提交副本。
- 独立 Docker 容器、持久化数据库卷、在线一致性备份、恢复脚本。

这是**两人使用的第一版异步服务**。实时看到对方走动、实时并坐/一起做饭、推送提醒和手机原生安装包仍未实现。名字目前为固定角色；所在地由主人设置，自动天气和手动天气可切换。音乐只在当前设备播放。基础食物可以免费补充，服务端执行账号/物品归属权限和数量上限，不是防作弊游戏经济系统。

## 部署到腾讯轻量云

按 [部署说明](DEPLOYMENT.md) 操作。适配现有 Ubuntu 24.04 + Docker Compose 环境；默认另开 8081，不修改现有 Nginx 或 Python 服务。无需购买独立数据库。

现有静态演示网站保持原地址和原版本。这个仓库只上传代码，不会自动改动已有网站。旧浏览器的本地存档**不会自动迁入云端**；可以先在旧网站导出文字手账。云端账号从新的独立存档开始。

## 两个人怎样使用

1. 第一位住户直接创建账号，并设置一个好记的加入口令（6–24 位字母或数字），私下告诉另一位。
2. 第二位使用这个口令注册，选择剩下的熊。账号名为 3–24 位字母/数字/下划线/短横线；登录密码至少 10 字符。
3. 一人在“账号与配对”生成配对邀请码，另一人在自己的账号里输入，完成双向连接。加入口令用于注册，配对邀请码用于连接星球。
4. 登录后不能再用“切换角色”访问别人的账号。
5. 去对方星球，将随身包里的零食放入冰箱，或用厨房食材做饭并选择留给对方。
6. 对方打开冰箱/餐桌发现礼物；食用后，双方手账能看到后续记录。
7. 写手账时选择“私人”或“共同”。共有手账只对配对双方开放，服务器管理员仍能通过数据库/备份访问数据，这不是端到端加密。

第一位住户可以在第二位注册之前，进入“账号与配对”修改加入口令。修改后旧口令失效。旧版本已有账号也支持此操作；升级保留账号和存档。新部署无需在服务器查找随机口令，请由主人先创建第一个账号。

页面空闲时约每 5 秒拉取一次最新存档；填写手账、操作模型或户外活动时不会强行刷新界面。若这段时间另一台设备修改了存档，本次保存会明确提示冲突，允许先导出未提交内容，再重新载入。**没有自动合并冲突**。同一账号多台设备也遵守这个规则。等待页面“已保存”再关闭页面；网络失败的草稿仅在当前页面内存里，刷新前请导出。

解除配对会停止新的互访和对方数据访问；双方各自保留自己的记录。已经看过或导出的内容无法从对方设备收回，重新配对后原来的共同内容再次可见。

## 本地开发

使用 Node.js 24，不需要 npm install 或前端构建。

- 云端模式：设置 PUBLIC_ORIGIN、PORT、DATABASE_PATH，然后运行 npm start。
- 单机演示：npm run demo，然后打开 http://127.0.0.1:4173。
- 后端测试：npm test。

默认云端本地端口 8080，默认来源 http://127.0.0.1:8080。PUBLIC_ORIGIN 必须和浏览器打开的网址完全一致，不带末尾斜线。服务端动态提供 runtime.js，静态托管使用仓库里的 demo 版本；云端接口故障不会静默退回本地存档。

## 代码与数据

- backend/server.mjs：HTTP 服务、密码哈希、会话、来源/CSRF 校验和限流。
- backend/store.mjs：SQLite 事务、配对、可见性过滤、存档权限与版本冲突校验。
- dist/cloud.js：登录注册、云端存档队列、同步与失败处理。
- dist/app.js 和其余 dist 模块：球面探索、立体家具、角色、宠物与生活互动。
- backend/admin.mjs、scripts/：备份恢复和管理员操作。
- tests/backend.test.mjs：账号、授权、赠礼、并发、持久化和 HTTP 集成测试。

数据保存在 Docker 命名卷 little-planet_planet_data 的 /data/planet.sqlite，**不在 GitHub 中**。密码使用独立随机盐和 scrypt，数据库内只存会话令牌/邀请码的哈希，自设加入口令也使用随机盐和 scrypt 存储。Cookie 为 HttpOnly、SameSite=Strict；PUBLIC_ORIGIN 使用 HTTPS 时自动加 Secure。数据库不是加密数据库，请保护服务器和备份。

## 验证与范围

已通过 Node.js 24 的后端测试，以及独立 Chrome 的双账号浏览器验收：注册、配对、冰箱模型赠礼/发现/食用、手账隐私、共同记录、退出再登录和 390×844 手机尺寸。已有 3D 功能的历史验收记录见 [原型迭代记录](docs/PROTOTYPE-HISTORY.md)。

本机没有 Docker 引擎：已检查 Compose 结构、脚本语法和实际后端/数据库运行，但尚未在你的腾讯服务器上启动容器。真实手机硬件帧率、弱网体验和服务器负载需要部署后继续验证。

模型为程序化原创几何；手账封面为 AI 生成插画。Three.js r170 使用 MIT 许可，见 dist/vendor/LICENSE-three.txt。字体远程加载失败时回退到系统字体。
