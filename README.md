# 阿球 Echoo · 双人云存档版

**打个喷嚏，是有人在惦记你。**

「阿球」取打喷嚏「阿秋」的谐音，把被惦记的温暖藏进名字里；英文名为 **Echoo**。

两个人各有一颗可以行走、旋转、进入小屋的 3D 星球。白熊“小禾”和棕熊“阿远”分别属于两个独立账号，用一次性邀请码配对后，能够异步互访、赠送零食、留饭、写共同手账。

## 这一版已经实现

- 小禾花园：六块种植地，可种玫瑰、郁金香、向日葵、番茄、胡萝卜、草莓。配对后双方可播种、浇水、采摘；花约 2 分钟、蔬果约 3 分钟成熟，离线继续生长，每株浇水一次可提前 30 秒。收获归采摘者，可插进任一小屋的餐桌花瓶或把蔬果放入冰箱。服务端校验成熟时间与采摘事务，避免重复领取。
- 阿远篮球场：可运球和投篮，指针进入绿色区域时投篮命中；投篮次数与命中数保存到云端。
- 两座小屋二层均有洗手间与衣柜，可洗漱、打开柜门、更换薄荷或暖橘围巾。播种、收获、插花、洗漱、换装、投篮均记录进手账。
- 两层小屋：一层厨房与客厅，楼梯通往二层卧室；床可躺下休息、起床，休息写入手账。二层有床头灯和书桌，上楼时展开二层视图。修正站立、步行、长椅与露营坐姿的接触高度。
- 星球和小屋占满一屏；页面不横向滚动，仍可拖动旋转星球。日常卡片、探索入口和天气控制收进右侧「日常」面板，点击展开。
- 两个真实账号：用户名和密码登录、服务器端固定角色、退出登录和管理员密码重置。
- 设备时钟与所在地天气：真实天气模式进入时自动获取设备大致位置（需 HTTPS 与用户授权），定位失败可选城市；Open-Meteo 自动同步温度、晴雨雪与日出日落，互访显示对方所在地时区；支持 HTTPS 设备定位和手动天气。
- SQLite 云端存档：冰箱、饭菜、随身包、庭院花盆、帐篷、宠物互动计数、足迹、手账、纪念日和珍藏。
- 24 小时有效的一次性配对邀请码；未配对不能访问对方的星球，支持解除配对。
- 异步互访：对方离线时也可以去做客，给对方留零食、做饭；接收方登录后发现、食用，并更新双方记录。
- 私人手账由服务器过滤，只传给本人；共同回忆和留言由双方查看。对方不能修改你的私人包、珍藏、天气或装扮，也不能冒充你写记录。
- 事务保存、版本冲突检查和重复提交保护；页面显示保存状态，断网或冲突时可以导出未提交副本。
- 独立 Docker 容器、持久化数据库卷、在线一致性备份、恢复脚本。

这是**两人使用的第一版异步服务**。实时看到对方走动、实时并坐/一起做饭、推送提醒和手机原生安装包仍未实现。名字目前为固定角色；所在地由主人设置，自动天气和手动天气可切换。音乐只在当前设备播放。基础食物可以免费补充，服务端执行账号/物品归属权限和数量上限，不是防作弊游戏经济系统。

## 部署到腾讯轻量云

按 [部署说明](DEPLOYMENT.md) 操作。适配现有 Ubuntu 24.04 + Docker Compose 环境；默认另开 8081，不修改现有 Nginx 或 Python 服务。无需购买独立数据库。

现有静态演示网站保持原地址和原版本。这个仓库只上传代码，不会自动改动已有网站。旧浏览器的本地存档**不会自动迁入云端**；可以先在旧网站导出文字手账。云端账号从新的独立存档开始。

## 注册与一对一配对

1. 任意用户都可以注册。账号名为 3–24 位字母/数字/下划线/短横线，密码至少 10 字符；白熊、棕熊可以重复选择。无需注册口令。
2. 登录后点击左上角阿球 Logo → 账号与配对。一人生成配对码，另一人选择「我有配对码」，粘贴后确认对方账号，再绑定。
3. 配对码有效 24 小时、只能使用一次。主动换码立即作废旧码，关闭/重开面板不会换码。绑定成功同时作废双方未使用的码。
4. 每人最多绑定一人；已经绑定的任一方不能再次配对。账号、私人书架和授权互相隔离。
5. 「账号与配对 → 解除绑定」需要确认；任何一方都可解除。各自星球风格、物品、个人书架、微信读书授权、音乐红心与所在地随账号保留。
6. 旧关系的记录存入「更多设置 → 过去的记录」，仅本人可查看和导出。它们不会自动分享到新的关系（即使重新绑定同一个人）。普通个人独处记录继续留在当前手账。
7. 共同手账只对当前配对双方开放；服务器管理员仍能通过数据库/备份访问数据，这不是端到端加密。

页面空闲时约每 5 秒拉取一次最新存档；填写手账、操作模型或户外活动时不会强行刷新界面。若这段时间另一台设备修改了存档，本次保存会明确提示冲突，允许先导出未提交内容，再重新载入。**没有自动合并冲突**。同一账号多台设备也遵守这个规则。等待页面“已保存”再关闭页面；网络失败的草稿仅在当前页面内存里，刷新前请导出。

解除配对会停止新的互访和对方数据访问；双方各自保留自己的记录。已经看过或导出的内容无法从对方设备收回，旧共同内容保留在个人历史归档，不自动重新分享。

## 本地开发

使用 Node.js 24，不需要 npm install 或前端构建。

- 云端模式：设置 PUBLIC_ORIGIN、PORT、DATABASE_PATH，然后运行 npm start。
- 单机演示：npm run demo，然后打开 http://127.0.0.1:4173。
- 后端测试：npm test。

默认云端本地端口 8080，默认来源 http://127.0.0.1:8080。PUBLIC_ORIGIN 必须和浏览器打开的网址完全一致，不带末尾斜线。服务端动态提供 runtime.js，静态托管使用仓库里的 demo 版本；云端接口故障不会静默退回本地存档。

## 代码与数据

- backend/server.mjs：HTTP 服务、密码哈希、会话、来源/CSRF 校验和限流。
- backend/accounts.mjs：多人账号、一对一事务、配对码、迁移和关系历史隔离。
- backend/store.mjs：SQLite 事务、配对、可见性过滤、存档权限与版本冲突校验。
- dist/cloud.js：登录注册、云端存档队列、同步与失败处理。
- dist/app.js 和其余 dist 模块：球面探索、立体家具、角色、宠物与生活互动。
- backend/admin.mjs、scripts/：备份恢复和管理员操作。
- tests/backend.test.mjs：账号、授权、赠礼、并发、持久化和 HTTP 集成测试。

数据保存在 Docker 命名卷 little-planet_planet_data 的 /data/planet.sqlite，**不在 GitHub 中**。密码使用独立随机盐和 scrypt，数据库内只存会话令牌/邀请码的哈希。Cookie 为 HttpOnly、SameSite=Strict；PUBLIC_ORIGIN 使用 HTTPS 时自动加 Secure。数据库不是加密数据库，请保护服务器和备份。

## 星球相机

右下角相机打开时保持当前镜头的位置、角度和景别。单指拖动旋转，双指捏合缩放、同向拖动平移；桌面支持滚轮缩放、Shift 拖动平移。没有镜头切换按钮，手势可放大到脸部特写。退出恢复原镜头。可设 3 秒倒计时，空闲时可选挥手、比心、托腮。照片为当前 3D 场景的 JPEG，不包含网页按钮。

照片默认私密，收进沙发相册的“日常”；也可点拍摄缩略图查看、下载、删除或分享给当前伴侣。取消分享或解绑后，服务端撤销对方访问。照片绑定账号，保存在 SQLite 的 account_photos 表，随 scripts/backup.sh 的完整数据库备份保存；普通代码更新不会覆盖。每账号最多 200 张，每张最长边 1600 像素，满额时提示整理，不会自动删除旧照片。保存失败保留当前照片供重试或下载，刷新前请处理。


### 腾讯 3D：真实接口验证（尚未连接设计界面）

服务器 `.env` 增加 `TENCENT_3D_API_KEY`，重建容器后执行：

```sh
docker compose exec -T planet node backend/test-tencent-3d.mjs status
docker compose exec -T planet node backend/test-tencent-3d.mjs generate
```

`generate` 首次提交一张沙发的真实 HY-3D-3.1 任务，指定 20,000 面；自定义面数可能额外消耗积分，按服务商账单收费。后续运行只查询既有任务，不重复生成。提交结果不明时会阻止自动重试，以免重复付费。排队/生成中可一分钟后再执行；任务有效期 24 小时，请及时查询下载。完成后的 GLB 存在 SQLite `tencent_3d_probe` 表中，随现有数据库备份保存。超过 32MB、超过 10 万面、外部资源引用暂拒绝导入。域名不在已核对范围时保留任务，不能通过重新生成解决。

导出已完成模型：
```sh
docker compose exec -T planet node backend/test-tencent-3d.mjs export
docker compose exec -T planet cat /tmp/echoo-tencent-sofa.glb > /tmp/echoo-tencent-sofa.glb
```

这是运维侧联通与真实产物验证，不是用户侧完整生成功能；没有用范例替代腾讯结果。密钥、带签名下载地址不打印到控制台。后续仍需模型实际视觉验收、家具交互适配及服装绑定。


### 网页自然语言创作（家具生成与服饰剪裁）

部署后，小屋书桌的设计窗口可以直接输入需求。`AI_API_KEY/AI_BASE_URL/AI_MODEL` 用于自然语言规划，`TENCENT_3D_API_KEY` 用于家具 GLB 生成，两者不可互换。普通用户不需要配置密钥。装扮和小屋不再展示预制示例按钮。星球仍使用原有外观设计接口。

- 家具支持新增模型、重生成形状、移动、缩放、旋转、调色和收起；双人沙发替换原窗边座位。其他新增家具须通过重叠与通道校验，座椅目前仅一层。生成默认 2 万面，腾讯按生成及自定义面数计费。
- 服饰由实际语言模型给出剪裁、配色、褶皱和纹样，客户端生成适配熊体型的网格并随坐姿变形。目前为无袖上衣、裙子、无袖连衣裙，支持纯色/格纹/条纹/圆点；不是腾讯任意服装 GLB 自动绑定，复杂帽鞋等会拒绝而不假装成功。
- 可在未保存的预览上继续描述。移动、缩放、调色不调用腾讯；改变外形会新生成，保留旧模型。确认保存才更新账户设计，支持历史恢复和向对方赠送剪裁服饰。
- 任务和模型保存在 SQLite，现有备份包含它们。任务由后端继续查询，关闭面板或重新登录可恢复进度。提交结果未知不自动重试以免重复收费。模型端点需登录且只允许本人/当前配对对象访问。
- 运行时把过大贴图缩至 2048，32MB 或 10 万面以上模型暂拒绝；每个账号模型原始数据暂限 128MB，房间最多 12 件新增物品。这是资源保护，不是使用次数配额。

已完成过腾讯沙发测试的管理员，可以把测试产物导入指定账号的预览，无需再次生成：
```sh
docker compose exec -T planet node backend/import-tencent-probe.mjs 你的登录账号名
```
导入不直接覆盖小屋。打开设计窗口后确认保存。

验证：`node --test tests/studio.test.mjs tests/tencent-3d.test.mjs` 为接口替身和持久化测试，不代表真实服务调用成功。发布前还需在配置了密钥的服务器实际输入新需求，验证语言服务、腾讯生成、下载、预览和保存的全链路。


### 腾讯文字设计切换（2026-10-02）

已配置 `TENCENT_3D_API_KEY` 时，`AI_TEXT_PROVIDER=auto`（Compose 默认）会将所有文字设计统一切到 `https://tokenhub.tencentmaas.com/v1` 的 `hy3`。Key 必须授权 hy3；旧 AI_API_KEY / AI_BASE_URL / AI_MODEL 不再用于该模式。没有腾讯 Key 的安装继续使用原自定义接口。显式 `AI_TEXT_PROVIDER=custom` 可保留旧接口；`tencent` 强制腾讯，缺少 Key 时不会偷偷回退。`TENCENT_TEXT_MODEL` 可覆盖型号，默认 hy3。Key 仅在后端使用。

腾讯 Hy3 和 Hy4-preview 按官方协议关闭 thinking，以支持指定工具调用；不自动切换付费模型。权限开通不代表免费额度，请以 TokenHub 控制台为准。家具 3D 生成接口保持原状。

更新重建容器后，可执行 `sudo docker compose exec -T planet node backend/test-tencent-text.mjs`。它在内存数据库中调用真实文字接口，校验服饰工具参数；不会发起 3D 生成，也不会修改用户作品。文字请求按服务商额度计费。自动测试使用模拟服务，不能替代服务器真实 Key 的验收。


### 装扮试穿与搭配（2026-10-02）

装扮编辑使用独立的三维熊预览，手机上下分区、桌面左右分区；拖动旋转、双指或滚轮缩放，关闭即退出预览。不会移动星球原镜头。已有贝雷帽/针织帽、软底鞋/短靴、蝴蝶结/胸针通过 AI style 操作搭配；accessoryColors 可独立指定帽、鞋、配饰颜色，并沿用保存、回滚、赠送流程。这是对现有模型的自然语言搭配，不是任意新帽鞋模型生成。服饰结构仍受裁剪参数限制。


### 自由生成作品（2026-10-02）

装扮的自然语言创作优先走 asset_create / asset_regenerate 的混元 3D 实际任务；不再把新帽子、包、饰品的描述映射到现成款式。自由家具按描述生成，decor 可表达任意静态家具品类；seat 为新增座椅，sofa 仍专指替换窗边固定座位。通道、尺寸和存储校验继续生效，新家具不会自动获得开门、收纳等专属动作。

wearables 存放生成资产与位置/尺寸/朝向/色调；hat 跟随头部，back/chest 跟随身体，睡眠时收起，帽子在耳机/雨具冲突时收起。asset_fit / asset_remove 不发起第二次 3D 生成。用户保存才落到账号设计，支持历史恢复、作品列表与赠送。作品模型存于原 SQLite 数据库，纳入原备份。

garment 是需要变形适配的衣裤鞋等作品。允许生成并独立展示，保存为“待适配”作品，不装到熊身上。尚未实现自动蒙皮、布料模拟或通用穿模修复，不能宣称任意衣服可直接穿。试戴的刚性模型也需用户检查效果并可继续调位。最多八件随身作品是性能约束，不是创意品类白名单。

新增/重新生成会使用腾讯 3D 额度。文字自检脚本有网络目标白名单，绝不会提交 3D 任务。自动测试使用模拟服务和本地 GLB 测试模型，只验证协议、持久化与渲染流程，不代表新作品已完成线上真实生成验收。
