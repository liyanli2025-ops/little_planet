# 书架、留歌与微信读书

小屋一层新增真实书架和唱片架。点家具或再次点击底部「小屋」打开菜单。

- 书架支持手动添加书名、作者、微信读书分享链接；默认仅本人可见，可逐本分享。
- 点击「带到长椅读」，角色会带书坐下；正文通过官方链接打开，感想写入自己的或共同手账。
- 到对方小屋的唱片架留一首歌：填写 QQ 音乐分享链接、歌名、歌手和留言。收件人可以收下心意、写回应。播放在 QQ 音乐官方页面完成。
- 共同手账沿用原有留言和权限逻辑；不会把点击音乐链接记成「听完」，也不自动收集阅读正文。

## 微信读书绑定

更新服务器后，使用 HTTPS 登录阿球，打开「账号与配对 → 微信读书绑定」。在 https://weread.qq.com/r/weread-skills 登录，获取个人 API Key，粘贴至阿球的密码输入框。无需把凭证发给开发者，也无需修改服务器环境变量。

当前使用 Tencent/WeChatReading 官方文档定义的 POST https://i.weread.qq.com/api/agent/gateway，接口 /shelf/sync，skill_version 1.0.4。
参考：https://github.com/Tencent/WeChatReading/blob/main/skills/SKILL.md 和 shelf.md。

同步为手动触发，包含电子书、有声书和文章收藏入口；不读取私人划线或笔记，不提供完整书籍正文。导入结果默认私人，逐本主动分享。重复同步更新同来源书籍，不重复添加；不会自动删除阿球里的书。同步上限 1400 个条目，超限整体拒绝并保留旧数据，不静默截断。

绑定凭证仅存在服务器 SQLite 的 weread_bindings 表内，账号各自隔离，不返回前端，不进入存档导出或手账。数据库文件本身未做字段加密；现有 Docker 的 /data 权限为 700，只有服务器管理员和应用进程可访问。完整 SQLite 备份也包含凭证，应像账号数据一样保管。解除绑定删除服务器凭证；如果要撤销已泄露或备份中的凭证，请在微信读书官方页面撤销。已导入的书保留。

本次无需额外依赖、数据库服务、端口或付费音乐接口。启动时自动增加 media_items 和 weread_bindings 两张表。现有 scripts/backup.sh 完整备份 SQLite，会一并保留新表。

验证：自动化测试采用官方回包结构的模拟接口，覆盖导入、权限、凭证隔离、失败保护和解除绑定竞态；没有真实用户凭证，首次真实书架同步需要用户绑定后确认。

## 封面与实际阅读进度

重新同步书架会更新官方返回的封面；书架中封面在上，书名、作者在下。未返回封面或图片加载失败时保留文字书封，不显示破图。远程封面只接受受信任的腾讯图片域名，通过 HTTPS 加载且不发送来源页。

打开已同步的电子书，点击「同步这本书的进度」读取 /book/getprogress，并结合 /book/chapterinfo 显示章节名称。显示阅读百分比和同步时间，1 表示 1%，不会误算成读完。目录获取失败不阻止百分比更新；进度请求失败保留旧结果。当前为手动同步，不是实时推送，不同步原书正文，也不推算当天页数。

共享书籍不会自动共享进度。主人可在书籍详情单独开启／关闭进度共享；未共享时服务端会移除对方能看到的进度和读完状态。手动添加的书、有声书和文章收藏入口暂不支持这个电子书进度接口。

## 阅读生活足迹与手账

每次手动同步单本阅读进度后，服务端在同一个数据库事务里更新进度与手账。首次同步留下「阅读起点」，明确是已有进度；以后百分比或章节变化才追加一条记录，达到 100% 时留下读完记录。相同进度重复同步不重复写入；进度回退按实际变化记录，不冒充新增阅读量。不推算当天页数或当天读了多少百分比。

这些记录使用现有生活足迹／手账系统，可珍藏、添一句话、分享或删除。创建时间为同步时间，正文另列官方返回的最后阅读时间（北京时间）。默认私人；同时开启书籍共享和进度共享时，后续产生的阅读记录进入共同手账。切换共享设置不追溯改变历史手账，历史记录在手账中单独管理。书籍详情新增「查看我的手账」入口。
